# 냉장고를 부탁해 — 발표 대본 (약 5분)

## 1. 냉장고를 부탁해

안녕하세요, 저희는 ‘냉장고를 부탁해’라는 냉장고 관리 에이전트를 만들었습니다. 오늘은 프로젝트 주제, 시스템 구성, 에이전트 그래프, 주요 프롬프트 순서로 소개하고, 검색 전략은 팀원이 이어서 발표하겠습니다.

## 2. 목차

발표 순서입니다. 1번부터 4번까지 제가 설명드리고, 5번 검색 전략은 팀원이 발표합니다.

## 3. 01  프로젝트 주제

냉장고에 재료를 사 두고 잊어버렸다가 결국 버린 경험, 다들 있으실 거예요. 그리고 매일 오늘 뭐 해 먹지 고민하죠. 그래서 저희는 냉장고 재고와 유통기한, 사용자의 일정과 취향까지 보고, 곧 상할 재료부터 쓰는 레시피를 추천하는 에이전트를 만들었습니다. 재료 등록부터 추천, 재고 반영, 평가까지 완성해서 지금 AWS EC2에 배포되어 동작하고 있습니다.

## 4. 02  시스템 설명

시스템 구성입니다. 화면은 Streamlit으로 만들었고, 로직은 Python, AI는 AWS Bedrock의 Claude를 씁니다. 평소에는 싸고 빠른 Haiku를 쓰고, 냉장고 사진처럼 어려운 인식에만 Sonnet을 씁니다. 데이터는 PostgreSQL에 저장하고, 레시피 1,151개는 임베딩과 함께 pgvector에 넣었습니다. 가장 중요하게 생각한 원칙은 ‘계산은 코드로, AI는 판단만’입니다. 유통기한, 재고 차감, 식단, 통계는 모두 테스트된 코드로 계산하고, AI가 만든 결과는 반드시 사용자가 확인한 뒤에 저장됩니다.

## 5. 02  시스템 설명

사용 흐름은 세 단계입니다. 영수증이나 냉장고 사진을 올리면 Claude가 재료를 뽑고, 사용자가 확인 표에서 고친 뒤 저장합니다. 채팅에서 뭐 해 먹지라고 물으면 3일 안에 끝나는 재료로 레시피를 찾아 줍니다. 이거 만들게라고 하면 재고에서 빠질 양을 먼저 보여 주고, 확정을 눌러야 실제로 빠집니다. 먹고 남긴 평가는 다음 추천 순서에 반영됩니다.

## 6. 03  랭그래프

에이전트의 핵심 구조를 LangGraph 형식의 그래프로 그리면 이렇습니다. START에서 model 노드로 갑니다. model은 Bedrock의 Claude Haiku 4.5입니다. model이 도구를 부르면, 즉 응답에 tool_use가 있으면 tools 노드로 가고, 없으면 END로 끝납니다. tools는 아래 8개 도구 중 요청받은 것을 실행하고, 결과를 들고 항상 model로 돌아갑니다. 이 반복은 최대 6번까지 합니다. 도구는 냉장고 보기, 요리 찾기, 취향 기억, 요리 후 네 가지로 나뉩니다. 특히 prepare_cooking은 재고 빼기 미리보기만 만들고, 실제로 빼는 건 사용자가 화면에서 확정할 때입니다. 참고로 LangGraph 라이브러리 자체는 쓰지 않고, 같은 구조를 lib/agent.py에 직접 구현했습니다.

## 7. 03  랭그래프

State가 어떻게 쌓이는지 예시로 보겠습니다. 사용자가 두부 며칠 남았어라고 물으면, 앱이 오늘 날짜를 앞에 붙여 user 메시지로 넣습니다. model이 get_expiring 도구를 부르면 assistant 메시지에 tool_use가 담기고, tools가 실행 결과를 user 메시지의 tool_result로 붙입니다. 다시 model이 이번엔 도구 없이 두부는 내일까지예요라고 답하면 END입니다. 이렇게 노드를 지날 때마다 messages 끝에 하나씩 더해지고, 질문이 이어져도 지우지 않고 계속 쌓입니다. State에는 messages 말고도 이번 대화에서 찾은 레시피, 확정을 기다리는 재고 빼기 같은 값이 함께 들어 있습니다.

## 8. 04  주요 prompt

채팅 에이전트의 시스템 프롬프트에서 핵심 규칙 네 가지입니다. 첫째, 순서를 정해 줬습니다. 추천할 때는 임박 재료를 먼저 확인하고 그 재료로 검색하게 했습니다. 둘째, 검색 결과에 있는 레시피만 추천하게 해서 없는 레시피를 지어내지 못하게 했습니다. 셋째, 알레르기 재료가 든 레시피는 절대 추천하지 않게 했고, 이건 코드에서도 한 번 더 막습니다. 넷째, 재고를 빼는 것 같은 실제 행동은 미리보기까지만 하고, 이미 뺐다고 말하지 못하게 했습니다.

## 9. 04  주요 prompt

사진 인식 프롬프트는 자유롭게 답하지 않고, 정해진 도구 형식으로만 답하게 고정했습니다. 영수증 줄마다 원문, 먹는 것인지 여부, 확신도를 함께 받아서 생활용품을 걸러 내고, 헷갈리는 항목은 사용자가 확인 표에서 고칩니다. 실제로 고수를 고추로 바꿔 읽는 일이 있어서, 비슷한 재료로 절대 바꾸지 말라는 규칙을 넣었습니다. 요리 후기는 Haiku가 취향으로 바꿔 기억합니다. 너무 짰어라고 남기면 짠맛을 싫어함으로 저장하고 다음 추천에 반영합니다. 확실하지 않으면 넣지 말라고 해서, 잘못된 취향이 쌓이지 않게 했습니다.
